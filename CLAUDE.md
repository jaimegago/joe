# CLAUDE.md

## Project Identity

Joe (Joe Operates Everything) is an AI-powered infrastructure copilot for platform engineers. A single binary — `joe` — runs the Core daemon (HTTP API on :7777) as its default behavior, with subcommands (`joe mcp`, `joe slack`, etc.) riding alongside. Joe is AI-agnostic — the LLM adapter abstracts the provider: native Anthropic (`claude`) and Google (`gemini`) adapters sit alongside a generic OpenAI-compatible adapter (`openai-compat`), selected by provider plus a config `base_url` and reachable against any server speaking the OpenAI Chat Completions protocol. The validated provider set is config-driven — `internal/llmfactory/factory.go` (the factory switch) and `internal/config/validation.go` (the allow-list) are authoritative. Joe builds a graph of infrastructure relationships backed by SQLite.

**License posture:** Joe is a personal, open-source portfolio project licensed **Apache-2.0** (`LICENSE` at the repo root is ground truth). Distribution is **published release binaries plus build-from-source**, the two as first-class peers (D-0122): a `v`-prefixed tag push triggers `.github/workflows/release.yml`, which runs `goreleaser release --clean` to publish a GitHub Release carrying the built archives (per `.goreleaser.yaml`'s `builds`/`goos`/`goarch` matrix) and a checksums file, with release notes from goreleaser's default changelog. `.goreleaser.yaml`'s `before.hooks` stage the real web UI (`scripts/stage-ui-for-release.sh`, the same source/dest the Makefile's `build-ui` target uses) before every goreleaser build or release, so a published binary never ships the placeholder embed. **The published artifact set is archives and a checksums file only** — `.goreleaser.yaml` carries **no `signs:` block**, so nothing is signed, and there is no install script, Homebrew tap, Scoop bucket, or distribution package; adding any of those is its own posture decision, not implied by the release existing. **The tag is operator-cut, never agent-cut or CI-cut** — see [`docs/RELEASING.md`](docs/RELEASING.md) for the procedure and `docs/backlog/release-pipeline.md` for the surviving post-tag work. This is independent of the separate `joe-sre-skills` starter repo, which is MIT.

## Architectural Invariants

> Before re-deciding anything architectural, consult [`docs/project/DECISIONS.md`](docs/project/DECISIONS.md) — the normative, append-only decision log (newest-on-top); where it conflicts with prose here, the log is the source of truth.

- Single `joe` binary: bare `joe` (or `joe --config ...`) starts the server (HTTP API + Core Agent + adapters + graph); subcommands (mcp, slack, skills, incident, db, panic, unlock) dispatch ahead of it. The server entrypoint lives in `cmd/joe/server.go`; the CLI dispatcher in `cmd/joe/main.go`
- Graph store is SQLite-backed — no Cayley. Edge types: the named set is the relation constants declared in `internal/graph/relations.go`, but `graph_edges.relation` is free-form TEXT with no CHECK constraint, so further types enter as inline string literals (e.g. in `internal/coreagent/`) that bypass the constant set — the declared constants are authoritative as names, but no fixed count is authoritative as the total
- The infrastructure graph is **deterministic-only** (D-0110): nodes and edges come **solely from Joe-authored adapter and refresher code** through the delta-reconcile seam (`LoadGraphStateForComponent` → `BuildGraphDelta` → `ApplyGraphDelta`), **never from LLM inference** — LLM-derived understanding, including any future IaC repository analysis, may not enter the graph. It has no designated home since D-0113 deleted the knowledge store's derived tier, which was to hold it; the bar on the graph stands regardless. The three onboarding-era graph-write tools (`graph_add_node`, `graph_add_edge`, `graph_update_node`) are **parked** out of the agent:core registry per the D-0081 pattern (implementations and `ActionRead` classifier rows retained; pinned by `TestGraphWriteToolsAreParked`) — they bypassed the delta seam and, being Read-classed, would have passed the write floor in observation mode. `graph.Edge.Confidence` is a heuristic-strength marker on a deterministic derivation (`Inferred` = name-match), **not** an authority tier
- **Component deletion cascades graph state transactionally** (D-0117): deleting a component removes **every `graph_nodes` row carrying its `component_id`** in the **same `mutateWithAudit` transaction** as the `components` row and the governed audit insert. `handleDeleteComponent` (`internal/api/components.go`) calls `graph.GraphStore.DeleteNodesByComponentTx` (`internal/graph/sqlite.go`, the Tx-suffixed `execContext` idiom) alongside `Components.DeleteTx`; ownership of graph tables stays with the graph store, never the component store. `graph_edges` rows die with their endpoint nodes by the migration-002 FK `ON DELETE CASCADE` on the transaction's connection (`foreign_keys=1` is DSN-encoded on every pooled connection) — **cross-component edges dying with their dead endpoint is correct**, since a per-component reconcile (`edgesBetween` needs both endpoints loaded) can only ever clean them by endpoint-node death. This is a **governed-upstream** graph write (gated by `requireAdmin`, run in the audited transaction) — the access guard recognizes it as graph access and exempts it by a **narrow (method, file)** carve-out, not a package-wide one. Pre-existing orphans are swept **once** by migration `032_prune_orphaned_graph_nodes` (`NOT EXISTS` over `components`, which sweeps NULL and empty-string `component_id` alike — neither can name a live component); there is **no recurring startup sweep**, which would mask a future regression of the cascade instead of letting `TestDeleteComponent_CascadesGraphState`/`TestDeleteComponent_CascadeRollback` catch it. The two web-UI Refresh buttons were removed with this (per-component Last Sync covers freshness)
- **Component IDs are format-validated at the registration seam** (D-0147): both registration surfaces — the governed HTTP create path (`handleCreateComponent`) and the `register_component` agent tool (as a post-generation assertion on its type-hyphen-hex IDs) — pass through `componentgov.ValidateComponentID` (`internal/componentgov/id.go`), a sibling of the other shared registration seams (`RejectCredentialFields`, `NormalizeRegistrationConfig`). The validator is authoritative for the rule; do not restate its constraints in prose or duplicate them elsewhere — the UI's client-side mirror (`ComponentRegisterForm.tsx`) is feedback only, never the gate. Validation fires at registration only; pre-existing rows are grandfathered. A **third** shared registration seam sits beside those two: `componentgov.ValidateRegistrationConfig` (`internal/componentgov/config.go`) enforces per-type **non-credential** config shape, today the format of any config field naming another component (git's `provider_component_id`), and both surfaces call it. It checks **shape, never existence** — a well-formed reference to a component that does not exist is accepted, because order-dependent registration would be a worse defect than a reference resolving to nothing; what consumes the reference decides what dangling means
- **Registrability is a per-type posture, and `git` is the one type that has taken the restore path** (D-0150, partially superseding D-0111 for git alone). A type is registrable iff it appears in `store.AllowedComponentTypes` / `IsValidComponentType`; the D-0111 trim's precondition for restoring any of the types it removed is wiring a credential path first, and git is the type that met it. **git is credential-wired with two kinds** (`internal/credential/wiring.go`): `KindStatic` as the type-level default (an HTTPS-token reference resolved from a named env var, reference only) and **`KindNone`** (`internal/credential/none.go`), the explicit no-credential arm for a public repository, which resolves to **no credential at all** so every typed accessor reports false. **Promotion is mandatory for both** — a public repository is inert until armed; `none` is a deliberate, admin-attributed, audited statement that Joe may reach that host unauthenticated and write a local copy, made legible in the audit row rather than left implicit in an empty locator list. This generalizes the boundary's framing: **promotion arms reach-out, usually but not necessarily by supplying a credential.** git is the second multi-Kind type and selects differently from kubernetes: kubernetes reads a stored `auth_method` at Connect, while git's `credential_provider` written at promotion **is** the selection. The legal pair is declared once in `credential.SelectableKinds` / `IsSelectableKind` — do not hardcode the pair at a call site, and do not state a count of registrable or wired types anywhere (D-0032). The git adapter resolves at the **use-time seam** like every other credential-wired adapter (`resolveAuth`, `internal/adapters/git/git.go`); it carries **no inline auth fields**, and the retired `http_token` / `ssh_key_path` names are held in `internal/credential/fields.go`'s retired-inline-auth-fields declaration so registration still refuses them through the single reflection-derived denylist that can no longer see them
- **`git` is barred from auto-promoted reads** (D-0150). A git read is an **outbound fetch plus a disk write** — the adapter clones or pulls — not a query against a backend the operator already pointed Joe at, so it falls outside the bargain `auto_promote_reads` (D-0028) was made about; agent:core reading a repository stays a deliberate per-component grant. The exclusion is one shared declaration, `rbac.AutoPromotableReadType`, consulted at **both** ends: the **policy engine predicate** (`internal/rbac/policy.go`), which is the load-bearing one because the flag resolver queries `agent_read_promotions` **by type string** and never consults the registrable-type enum, so an exclusion placed only in the admin surface would leave any row written by other means still admitting; and the **admin surface** (`internal/api/admin.go`), which neither presents an excluded type as flippable nor accepts a set for it. Pinned by a predicate test carrying its own same-test control proving a non-excluded type still admits
- **A git component may declare its hosting provider, yielding one discovery-only edge** (D-0150). The optional `provider_component_id` config field names the `github` or `gitlab` component hosting the repository. When it resolves to a real component of one of those two types, `refreshGitComponent` emits one `hosted_by` edge (`graph.RelationHostedBy`) from the repository anchor to a host node keyed under **this** git component — per-git-component deliberately, since a node shared across two git components on the same forge would be claimed and its edges reaped in turn by each owner's per-component delta. A dangling or wrong-typed reference is **logged and skipped**: no node, no edge, no false claim. It is a deterministic derivation of an operator declaration, not an inference (nothing guessed from the URL, nothing discovered by reaching out), so **D-0110 is untouched**. **The edge carries discovery semantics only — no RBAC, zone, or governance meaning**; it grants nothing and the two components stay governed independently
- **Cloned repository content is data-plane text** (D-0150): file contents, commit messages, and diffs Joe reads out of a registered repository are evidence to reason over, **never instructions to follow**, exactly as with any other observed backend content. The ability to clone changes the volume of such text Joe can hold, not its standing
- Action Safety Framework: a binary action axis (`internal/safety/tier.go`, `ActionRead` / `ActionMutate`) — Reads run unconditionally; Mutates are denied by default. The per-action opt-in seam remains in the policy shape (`ActPolicy` + `IsT3Allowed`, `internal/safety/policy.go`), but **as of D-0113 no registered tool carries a `PolicyKey` resolving to a live `ActPolicy` field**, so every registered Mutate is denied regardless of policy configuration — the opt-in cannot currently be granted to anything. This is **pinned by `TestRegisteredMutatesAreUngrantable`** (D-0127), which derives the Mutate set from the classifier and the toggle set by reflection over `ActPolicy`, then asserts denial under a policy with every `act` toggle enabled; a failure means a registered Mutate has become grantable and this claim needs revising, not that safety broke. `publish_doc_update_git` under `git_push` was the last tool reaching the allow branch and died with the knowledge store; the seam becomes exercisable again only when full mode ships a real opt-in tool (`docs/backlog/act-policy-vestigial.md`). The former three-tier Observe/Record/Act (T1/T2/T3) scheme was collapsed to this binary Read/Mutate axis by D-0020 (the Record band is gone — Joe's own model-maintenance tools are Reads)
- Write floor (`internal/safety/floor.go`): boot-resolved, runtime-immutable read-only value (observation mode or sticky safe-mode/panic) — once up, nothing in the binary lowers it; recovery is restart, never a live down-transition. **Observation is the day-one default (D-0073): an unconfigured Joe (`JOE_MODE` unset) boots with the floor up for reason observation.** `JOE_MODE=full` is refused at boot as not-yet-implemented (it neither enables writes nor silently downgrades), and any unrecognized value is refused fail-closed — the raw value is mapped by `env.ResolveBootMode` before floor resolution, ahead of and independent of panic precedence. `ResolveWriteFloor`'s writable resolution (observation input false) is retained as the seam for full mode when it is built
- **Boot fails closed on a key/database mismatch** (D-0120), in two rules, both fatal. **Rule A:** `crypto.LoadOrCreateKey` takes an `EncryptedDataProbe` and its generate-on-absence branch is **conditional** on it — the composition root supplies it from `store.ScanComponentConfigs` (the single home for the encrypted-marker detection: unmarshal the config column as a JSON string, then `crypto.IsEncrypted`, because the value is JSON-quoted **and** carries BLOB storage class despite the TEXT declaration, so SQL `LIKE` matches nothing). No encrypted rows → genuine first boot, generate. Encrypted rows → refuse, write no key. The probe answers about **data, not rows** (a plaintext backward-compat install is still a first run); a probe error and a nil probe both refuse, since minting is the irreversible direction. **Rule B:** `EncryptedComponentRepository.VerifyConfigs` runs once at boot after wiring and refuses if any stored config fails AES-GCM authentication. **Accepted trade-off: one corrupted row also prevents boot** — GCM cannot distinguish wrong-key from row corruption and no heuristic was invented; the mitigation is that the check does **not** stop at the first failure but enumerates **every** failing component, so "all of them" reads as a wrong key and "one of them" as a damaged row. Only the authentication class refuses (typed seam: `crypto.ErrAuthentication` wrapped by `store.ConfigAuthError{ComponentID}`, branched on by class, never by message text); transient store errors keep their prior posture. The `component credential encryption enabled` log prints **below** the verification so it asserts something proven. The key path is configurable via `database.encryption_key_path` / `JOE_DATABASE_ENCRYPTION_KEY_PATH`, resolved by the single helper `encryptionKeyPathFor` (`cmd/joe/db.go`) that both boot and `joe db restore` use; it **mirrors `database.dsn` including the no-`~`-expansion trap**, deliberately, so the two paths in one config block behave identically. There is **no escape hatch** for a deliberate start-over (delete the database or `joe db restore`); do not add a `--force-new-key`
- Denial precedence is floor > incident > RBAC, ordered by resolvability depth and enforced by check order in the executor (`internal/tools/executor.go`) — not by per-check return values
- Read posture (D-0041, scoped by D-0043; `internal/readposture/` + `internal/rbac/policy.go`): a single persisted, install-wide scalar selects the **human-facing transport** read decision. The launch default is **`team_flat`** — every authenticated principal reads every component, regardless of grant; the admit sits after the zone-allows-action gate (it widens WHO may read a permitted action, never WHICH actions a zone allows) and fires for the read action only. **`zoned`** is the grant-based full-mode read path (the prior zone+grant behaviour, unchanged). The posture is read live per request (no boot cache); the flip is an admin-gated, audited operator act on the admin REST surface. The posture governs **human-facing transport reads only** and has **no effect on the agent:core autonomous read surface**: the read-posture resolver is wired into the transport policy engine alone (`NewPolicyEngineWithGovernance`, built once at the composition root in `cmd/joe/server.go`'s `buildHTTPHandler` and injected into `api.New` so the guarded accessor enforces with it), never the agent:core refresh engine (`NewPolicyEngineWithPromote`, posture seam nil), so the two axes are separated at engine construction and flipping the posture cannot change what `agent:core` can read. The autonomous read surface is governed solely by `auto_promote_read` (per-component-type promotion) plus grants. The write floor and write-RBAC govern mutates **independently of read posture** — a `team_flat` install with the floor up still denies every mutate
- The **kubernetes graph refresher degrades per-resource-type on forbidden, it does not hard-fail the tick** (D-0093, `internal/coreagent/k8s_refresh.go`). A list call denied by RBAC (detected via the apimachinery typed-error helper through error unwrapping, never string matching) records a skip for that resource type and continues; the tick still applies its delta from the types it could list, and the now-forbidden type's previously-discovered nodes are reconciled out (the graph reflects what the credential can observe). **Forbidden is the only degradation trigger** — any non-forbidden list error retains the abort-with-wrapped-error, no-delta semantics. A tick that completes with skips writes a third component status, `degraded` (reusing the `status`/`last_error` columns via `store.UpdateSyncState`; no migration), with transition-based logging (Warn on change vs. the persisted `last_error` baseline, Debug when steady). Scope is the kubernetes refresher; the aws/azure/git refreshers still hard-fail (deferred, `docs/backlog/refresher-rbac-degradation.md`)
- Credential env-var names are **operator-supplied, stored verbatim, and enforced unique across the whole component set** (D-0061, generalized by D-0062). The locator is never computed or componentID-derived; promotion rejects an `env_var` already in use by another component. Because the component `config` blob is encrypted at rest, the guard is an application-level decrypt-and-scan at the promotion seam (`staticEnvVarConflict` in `internal/api/components.go`), not a DB UNIQUE constraint. The peer scan is **Kind-agnostic and process-global**; the call-site gate fires for **any promotion writing an `env_var` locator** — the generic static Kind OR the kubernetes static-bearer env-var source — because env-var names are process-global. The in-cluster token source carries no env var and is exempt. **The entra-exchange client secret is referenced under a DISTINCT field `client_secret_env_var` (not `env_var`) and is therefore intentionally exempt from this guard** (D-0063): one Azure app registration may legitimately front many clusters, so two components sharing one `client_secret_env_var` is a valid shared-app case, not a collision. Indirection-only is preserved — inline `value` and empty `env_var` are still refused. Pre-existing collisions are unhealable by code (forward-prevention only; no migration)
- The **Kubernetes transport is a hand-built `*rest.Config`** with **no kubeconfig ingestion** (D-0062). `buildRESTConfig` (`internal/adapters/k8s/k8s.go`) sets exactly three fields — `Host` from the `api_server` coordinate, `TLSClientConfig.CAData` from the stored inline `ca_data` bundle, and `BearerToken` from the resolved credential — and **never** sets an exec provider, auth provider, or impersonation. The k8s component `Config` carries the cluster coordinates (`api_server`, `ca_data` inline PEM, optional `namespace`) plus an `auth_method` discriminator (`internal/adapters/k8s/config.go`). Kubernetes resolution is **per-component**: the adapter reads `auth_method` and maps it to a credential Kind (`kindForAuthMethod`, exported to the promotion boundary as `KindForAuthMethod`), the seam later slices extend; the accepted methods are `static-bearer` (long-lived bearer token) and `entra-exchange` (D-0063, an Azure-Entra-minted token for AKS). The same per-component seam is mirrored at the **promotion boundary**: the wired default Kind stays `KindStaticBearer`, but for a kubernetes component the stored `auth_method` selects the effective Kind so the written discriminator and validated shape match what the adapter resolves at Connect. The stance is pinned by a **structural break-test** (`transport_break_test.go`) asserting `clientcmd` (the client-go kubeconfig loader) is absent three ways: from the k8s transport package, from `internal/credential`, and repo-wide from every production package except the accepted-importer set `{internal/adapters/packaging/helm, internal/adapters/networking/nginx}` (the two legitimately kubeconfig-shaped adapters). `clientcmd` remains a legitimate module dependency (helm/nginx use it) and is **not** removed; the guard confines it so it can never re-enter the transport or credential path (D-0064). The kubeconfig-exec provider that once carried the kubernetes transport is **retired and deleted** (D-0064); the two live auth methods above are the whole of it
- **`static-bearer` and `entra-exchange` are each their own credential Kind** (`KindStaticBearer`, `internal/credential/static_bearer.go`; `KindEntraExchange`, `internal/credential/entra_exchange.go`), distinct from the generic `KindStatic`. static-bearer resolves a long-lived bearer token from an **env-var source** (call-time `lookupEnv`, name-only stored) or an **in-cluster source** that reads the pod-mounted service-account token **directly** via `os.ReadFile` of the mount path — deliberately **not** `rest.InClusterConfig()`. entra-exchange (D-0063) **mints a short-lived bearer token** via an **Azure Entra OAuth2 client-credentials exchange** using the **already-vendored `golang.org/x/oauth2/clientcredentials`** (no new dependency, no Azure SDK); tenant id, client id, audience/scope, and the client-secret reference are **all per-resolution config values** — the provider **hardcodes no audience or tenant** and **imports no kubernetes or Azure-SDK symbol**, so it is **transport-agnostic and reusable** (pinned by an AST imports-only break-test in `entra_exchange_test.go`). The client secret is resolved by reference via the call-time `lookupEnv` under the distinct `client_secret_env_var` field. **Both Kinds' resolved credential is a bearer token applied through the same `Resolution.BearerToken()` accessor**, which is gated on a **bearer-Kind set** (`isBearer`), not a single Kind — so a minted Entra token rides the identical adapter consume-seam (`resolveBearerToken` → `BearerToken()` → `buildRESTConfig`) with no adapter change. Per-Kind locator requirements live in `internal/credential/requirements.go` (static-bearer: `env_var`/`in_cluster`, at-least-one; entra-exchange: `tenant_id`/`client_id`/`audience` required plus an at-least-one-of over `{client_secret_env_var, federated_token_file}`, the federated source reserved/designed-for but not built). kubernetes's wired default is `KindStaticBearer` in `wiredTypes` (`internal/credential/wiring.go`); the per-component `auth_method` selects entra-exchange
- **Web search is a Go-native shared Read tool** `web_search` (`internal/tools/shared/websearch/`, D-0064), a sibling of the other `internal/tools/shared/` tools that satisfies `tools.Tool` and never reaches the coretools client or accessor seam. It **discovers URLs** (returns ranked title/url/snippet only, never page bodies) and is distinct from `http_request`, which **fetches a URL the model already holds** — search and fetch stay separate and compose. It carries an **explicit `ActionRead` row in the `toolRegistry` map** (`internal/safety/tier.go`) so it passes the write floor unconditionally; without that row `ClassifyTool` would default it to `ActionMutate`. Backends sit behind the **`SearchProvider` abstraction** (`internal/search`: `Provider` interface + `NewProvider` boot factory) that mirrors the LLM-adapter factory in spirit — provider name + `base_url` + optional key, **no silent default** (empty provider → nil `Provider`, web search inert). **SearXNG** is the only provider implemented (keyless self-host); keyed providers (Tavily, Brave) are a designed-for additive extension deferred to `docs/backlog/web-search-tool.md`. Config is **boot-only** (`config.WebSearchConfig` + `JOE_WEBSEARCH_*` env, resolved once in `cmd/joe/server.go`, sealed onto `core.Services.WebSearch`, threaded into `registerSharedTools`); no runtime swap surface — changing the backend requires a restart, and a misconfigured backend is fatal at boot. **Exposed-and-deny**: unconfigured, the tool stays registered/advertised and returns a `no search backend configured` tool-error. Registered on the **user task loop only** (`internal/tools/default.go`); the autonomous `agent:core` registry (`internal/coreagent`) does **not** include it. Egress is to the single configured `base_url` with no allow-list, no rate limit, and no audit row — the shared-tool posture (external-network egress is not a gate dimension)
- **Joe has no knowledge store.** The `internal/knowledge` subsystem — the entry/source store, semantic search, the Confluence/Notion sync arm, the drift detector, and the doc-proposals pipeline — is **deleted** as of D-0113, not parked, per the D-0074 rule that the tree describes only what the binary ships. With it went the curated/synced/derived tier vocabulary, the `search_knowledge` / `detect_doc_drift` / `generate_doc_draft` / `publish_doc_update` tools and their classifier rows, the parked `save_knowledge_entry`, the MCP `joe_knowledge_search` tool, the `knowledge` config block, and the `knowledge_entries` / `knowledge_sources` / `doc_proposals` tables (dropped by migration 031). **Do not reintroduce a knowledge store, a tier taxonomy, or a doc-proposal path by extending the old shape** — a v2 is a ground-up design decision, unmade. The one live constraint it inherits: LLM-derived inferences (including future IaC-repo analysis) may **never** enter the infrastructure graph (D-0110), and the derived tier that was to hold them no longer exists, so a v2 must decide their home before that work starts
- Embeddings are gone with the store: `llm.LLMAdapter` carries **no `Embed` method** and there is no embeddings package. Knowledge was its sole consumer; the three adapters' implementations and the decorator pass-throughs were deleted with it. A future embedding consumer re-adds the method deliberately, rather than inheriting a stub that two of three adapters never implemented
- OpenTelemetry instrumentation goes in middleware/decorators, NOT in business logic
- Build truth has a single source, `internal/buildinfo`: every consumer (the `GET /api/v1/status` and `GET /api/v1/version` handlers, the `joe_build_info` gauge) reads it via `buildinfo.Get()`. The ldflags `-X` injection targets are that package's `Version`/`Commit`/`BuildTime` vars **addressed by full import path** (e.g. `github.com/jaimegago/joe/internal/buildinfo.Version`); no other package declares build-identity vars — **pinned by `TestGuard_BuildIdentityDeclaredOnlyInBuildinfo`** (`internal/buildinfo/build_identity_guard_test.go`), a repo-walking structural guard that fails on any production `const`/`var` outside `internal/buildinfo` naming build identity with a literal value; it matches on a **closed name set intersected with a value shape**, never a "contains Version" substring, so protocol versions, schema versions, and dependency pins stay out of scope. Widening the name set is never the way to make a violation pass. The MCP handshake's server version (`internal/mcp`) and the OpenTelemetry resource's `service.version` (`internal/observability`) both read `buildinfo.Get().Version`; the MCP **protocol** version is a distinct concept, stated by the mcp-go library, and is not build truth. `dev`/`none`/`unknown` appear only on a deliberately unset build. The `ui_digest` field is **not** injected — it is computed once at boot from the embedded UI FS (`webui.DistFS()` → `buildinfo.Init`), so it cannot disagree with the bytes the binary serves
- Technical layer organization (`internal/llm/`, `internal/tools/`, `internal/graph/`) is intentional — Joe is a single-purpose tool, not a multi-domain business app
- Core Agent autonomy levels: Autonomous (deterministic) -> LLM+Auto (high-confidence) -> Needs Human. The Needs-Human branch is a design level, not shipped — the autonomous refresh loop ships the deterministic tier only and has no escalation/queue path (the onboarding-and-clarifications subsystem that once backed it was deleted wholesale in D-0118, superseding D-0081's park)
- The **agentic loop reaching its iteration cap is not a hard-fail** (D-0100, `internal/agentloop/agent.go`). When `Agent.Run` exhausts `maxIterations` (default `DefaultMaxIterations`, per-request overridable via `taskConfig.MaxIterations`) without a tool-call-free answer, it makes **one forced-synthesis `Chat` call with no tools offered** (prompt `prompts.MaxIterationsSynthesis`), asking the model to answer from the evidence already gathered and state what is verified vs. unverified. Non-empty content → the run **completes** carrying that answer and `stop_reason` `max_iterations` (surfaced on the task response / SSE final event and persisted on the assistant `chat_messages` row, so a reload renders an amber truncation notice); errored/empty content → falls through to the retained `ErrMaxIterations` sentinel and terminal status `max_iterations_reached`. The synthesis call is observer-silent (iteration count is unchanged) and writes exactly one `llm_max_iterations_reached` audit row per cap hit either way. The cap now bounds tool spend, not the ability to answer; an errored tool call counts full price against the budget (D-0096). Do not hardcode the cap's numeric value in prose (D-0032) — cite `DefaultMaxIterations`
- **A tool-call-free response is not self-evidently a final answer** (D-0103, `internal/agentloop/agent.go`). The loop's completion signal is "no tool calls", but a model can **narrate** the tool call it is about to make and omit the call itself (measured on `gemini-2.5-flash` at ~16-20% of turns), which read literally ends the run as a *success* carrying the narration as the answer — Joe announces a step and stops, no answer, no error. `Agent.Run` therefore **probes** every tool-call-free response before accepting it: one Chat call replaying the model's own text plus `prompts.UnfulfilledToolIntentProbe`, **with tools offered**, asking it to make the call it promised or reply `DONE`. **Only tool calls are harvested** — the probe's text is discarded, never returned and never persisted, so a genuine final answer reaches the user exactly as first written. On recovery the loop writes back one coherent assistant message (narration + recovered calls) and the probe instruction never enters history. A failed probe is non-fatal (accept as final). It is provider-agnostic (in the loop, not an adapter) and costs exactly one extra Chat call per turn, billed like any other. The probe wording is empirically tuned — a pushier draft forced spurious calls on finished turns — so **do not reword it without re-measuring both directions** (recovery rate AND spurious-call rate on a finished turn)
- All LLM prompt strings live in `internal/prompts/` — not scattered across packages
- Chat sessions are a core subsystem (first-class owned/shareable/incident-linked sessions); its as-built specification is normative in [`docs/reference/DESIGN-CHAT-SESSIONS.md`](docs/reference/DESIGN-CHAT-SESSIONS.md) — consult it before changing session behavior

## Repo-Specific Conventions

- `joe` subcommands: `joe mcp`, `joe slack`, `joe skills`, `joe incident`, `joe db`, `joe admin`, `joe panic`, `joe unlock`, `joe version`, `joe help`
- `joe version` (D-0143) prints this binary's build identity — `version`, `commit`, `build_time`, `ui_digest`, one `key: value` line each on stdout — and is the **offline** build-identity surface beside `GET /api/v1/version`, which needs a booted, authenticated server. It boots nothing and reads no config. The first three fields are the ldflags-injected `internal/buildinfo` variables (`dev`/`none`/`unknown` when uninjected); `ui_digest` is computed at call time over the embedded UI via the same `buildinfo.Init(webui.DistFS())` pair boot uses, so a placeholder-embed binary reports the placeholder's digest truthfully. Do not assert a literal digest anywhere — it differs between a placeholder-only build and one carrying a staged UI; compare against `buildinfo.Compute(webui.DistFS())`
- **CLI argument rejection is uniform, and usage errors exit 2 (D-0136).** Every subcommand and sub-subcommand rejects an **unknown flag** and a **surplus positional argument** rather than silently ignoring it; where a command legitimately takes positionals, it checks the arity it actually accepts. **A usage error exits 2** — a flag-parse failure, an unknown flag, a wrong number of positionals, or an unknown sub-subcommand, i.e. anything decidable from the invocation alone. **An operational failure exits 1** — anything after the invocation was understood: a missing file at an explicitly named `--config` path, a store failure, a refused grant, a network error. The shape is a `flag.FlagSet` with `flag.ContinueOnError` writing to stderr, an explicit `fs.NArg()` check with a message naming the command, and unchanged handler signatures; `cmd/joe/cli_arg_rejection_test.go` pins it per command, with the flag-parse and arity checks asserted independently. Two deliberate exemptions, both reasoned in D-0136: `joe incident list` is a stub that exits 2 and does no work regardless of what follows it, and the **daemon path** discards its own flag-parse error on purpose (`resolveConfigPath`, `cmd/joe/server.go`) so a bad flag cannot stop Joe booting. **Requested help is not a usage error and exits 0 (D-0143):** an explicit `-h`/`--help` on any command, plus `joe help` and a leading `joe --help`/`joe -h`, prints the usage text to **stdout** and exits **0**, and the top-level forms do so before any config resolution, logging, or daemon boot. One shared helper, `parseCLIFlags` (`cmd/joe/main.go`), owns the split — it silences the `FlagSet` during `Parse`, then routes `flag.ErrHelp` to stdout with 0 and every other parse failure to stderr with its message and 2 — so call sites no longer set the FlagSet's output themselves. The unknown-command path still exits 2. The top-level intercept keys on the **first argument only**, so `joe --config x --help` keeps the daemon routing; that boundary is forced by the daemon flag-parse exemption above. Residue: `skills`/`incident` **leaf** help still runs behind their config load (`docs/backlog/cli-version-and-help.md`).
- **`--config PATH` is uniform across the CLI (D-0132).** It is carried by the daemon and by **every subcommand whose behaviour a config file governs** — named structurally, not counted: the daemon plus `panic`, `unlock`, `skills`, `incident` (its server-contacting members), `db backup`, `db restore`, and `admin bootstrap`. It is **withheld from `joe mcp` and `joe slack`**, which call `config.Load` on no path and take their whole configuration from the environment (`JOE_SERVER`, `JOE_API_KEY`, `SLACK_*`); a flag there would advertise a redirect it does not perform. The flag means the same thing everywhere — the daemon's name and semantics — and one function, `resolveConfigFlag` (`cmd/joe/main.go`), holds the **missing-file asymmetry** every command shares: a missing file at the **default** path keeps that command's existing behaviour (`config.Load` returns defaults), while an **explicitly named** path that does not resolve exits **1** with a message naming the flag. Absent the flag, every command behaves exactly as it did before the flag existed. `JOE_CONFIG` is honoured by the **daemon only**; no subcommand reads it. Where a command reads more than one thing out of a config — `db restore` (the database it replaces *and* the `database.encryption_key_path` it checks beside it), `incident` (address *and* key), `skills` (`skills.trusted_sources` *and* the reload target), `admin bootstrap` (service accounts *and* the database) — there is **one load and one `*config.Config` threaded as a value to every use**, so a partial redirect is unrepresentable rather than merely avoided. Commands taking positionals accept the flag on either side of them: via `reorderFlagsFirst` with `config` registered as value-taking (`db backup`, `db restore`, `admin bootstrap`), or via `splitConfigFlag`, which lifts the token out ahead of dispatch for the two commands that load config before reaching a sub-subcommand's flag set (`incident`, `skills`)
- `joe admin bootstrap PRINCIPAL [--config PATH]` (D-0129; `--config` added by D-0131, `cmd/joe/admin.go`) grants the **first** admin on a database that has none, offline, with no daemon contact. `--config` mirrors the daemon's flag exactly (D-0132 generalized it across the CLI; the asymmetry rule this command established now lives in the shared `resolveConfigFlag`); the **single** loaded config is threaded into the store seam (`deps.openAdminStore(cfg)` → `databaseConfigFor`, `cmd/joe/db.go`), so the service-account set the principal is validated against and the database the grant is written to redirect together or not at all. Absent the flag the default path is used unchanged; an explicitly-named path that does not resolve exits 1 rather than falling back to `config.Load`'s missing-file defaults. It exists because a deployment configured with service accounts and **no identity provider** cannot mint an admin at all: the OIDC login/callback routes are never registered, so the `auth.admin_email` bootstrap writer is **structurally absent**; `RBACEnabled` is true, so `requireAdmin` genuinely enforces; and the last-admin guard blocks the fall from one to zero. Zero admins is an absorbing state, and this is the only exit. **It accepts service-account principals only** (`svc:<name>` or the bare name, resolved against `server.service_accounts` and minted through `rbac.ServicePrincipal`, the same single point the authenticating request path uses). Human identities are refused outright: with no IdP a `user:` principal can never authenticate, so the grant would sit inert and arm later for whoever first presents that identifier; with an IdP, `auth.admin_email` already is the bootstrap path. Operators should configure a **dedicated** administration account rather than promoting the shared general-purpose key. **It is refused the moment any admin exists — there is no `--force` and no override, deliberately**; every later grant is forced through the audited `POST /api/v1/admin/admins`. The one-shot guarantee is **atomic in the statement, not the transaction**: `rbac.SQLRepository.AddFirstAdmin` carries its own `NOT EXISTS` predicate inside the INSERT and checks rows-affected, so a check-then-write race cannot grant twice (pinned by `TestAddFirstAdmin_ConcurrentInvocationsGrantExactlyOne`). It **runs migrations** on open (following `joe unlock`, not `joe db backup` — this command's promise is a write, and its tables must exist) and carries **no occupancy refusal**: one small transactional write is exactly what WAL + `busy_timeout` supports beside a live daemon, which picks the grant up with no restart since the policy engine reads admin status at decision time
- **The `admin_principals` writer set is closed and machine-checked** (D-0129). Every write routes through the shared grant helper `auth.Provisioner` (`internal/auth/provision.go`), which is the sole caller of the repository's `AddAdmin`/`AddFirstAdmin` — bypassing it would re-implement or drop the redundant-policy cleanup that keeps admin authority in exactly one table. The helper is in turn reached from exactly three sanctioned writers, named structurally rather than counted (D-0032): the OIDC callback's `admin_email` bootstrap (`internal/auth/handlers.go`), the `requireAdmin`-gated REST surface (`internal/api/admin.go`), and the offline first-admin CLI (`cmd/joe/admin.go`). Both layers plus a raw-SQL check are pinned by `internal/rbac/admin_writers_guard_test.go`, which walks the tree from a module-anchored root, skips nested modules (worktrees/vendored copies), excludes `_test.go`, and **fails loudly rather than vacuously if it finds zero call sites**. The two grant paths differ only in provenance: `granted_by` is `bootstrap_admin_email` for the first two and the value migration 016 reserved, `cli`, for the third. The CLI's audit actor is `auth.ActorCLIBootstrap` (`cli:admin-bootstrap`) — there is no authenticated caller, and naming the granted principal would assert a self-escalation that did not happen; the `cli:` prefix is unreachable from every principal-minting path, so it cannot collide with a real identity
- `joe db backup DEST [--config PATH]` (D-0114; `--config` added by D-0132, `cmd/joe/db.go`) copies the SQLite store via `VACUUM INTO` and is **safe against a live Joe** — the WAL means committed data can sit in the `-wal` sidecar, so copying `joe.db` alone can yield a valid-but-empty file. It opens the database directly and deliberately does **NOT** run migrations (diverging from `joe unlock`'s `defaultOpenPanicStore`, which does): backup must not upgrade the source as a side effect of a command that promises a copy. It refuses an existing DEST unless `--force` — an up-front `os.Stat` closes the engine's silent-clobber window for 0-and-1-byte destinations — binds DEST as a parameter, and refuses a non-SQLite driver (it is not a dialect-migration mechanism)
- `joe db restore SRC [--config PATH]` (D-0115; `--config` added by D-0132, `cmd/joe/db.go`) is backup's counterpart, and also runs **no Migrate**. It opens SRC **read-only** (`file:` URI + `mode=ro`; **never `immutable=1`**, which ignores a `-wal` and misreads a WAL-carrying source as empty) and copies with `VACUUM INTO` from that handle, so a SRC carrying a live `-wal` is normalized into one complete file. Pre-flight refuses: a failed `integrity_check`, a database with no `components` table, encrypted component config with no key file (override `--allow-missing-key`), a target another process holds open (**no override** — stop Joe), and an existing target (override `--force`). `--force` and `--allow-missing-key` are **separate and neither implies the other**. Restore never opens the target through `store.New` — that open would create the sidecars it removes. Detect encrypted configs by **mirroring the production read path** (JSON-unmarshal the config column to a string, then `crypto.IsEncrypted`): the value is JSON-quoted **and** stored with BLOB storage class despite the TEXT declaration, so SQL `LIKE` matches nothing. Target `-wal`/`-shm` are deleted before writing as **defence in depth, not the load-bearing protection** — `VACUUM INTO` already resets a stale WAL; the substitution hazard bites the **hand-restore**, which is why the published procedure carries a mandatory sidecar-deletion step. Occupancy is a write-free `BEGIN IMMEDIATE` under `locking_mode=exclusive` with the pool **pinned to one connection** (else it self-contends), classified by SQLITE_BUSY code, never message text. The target database and the encryption key are resolved from **one** loaded config threaded to both seams, so `--config` cannot move the database while the key is checked against a different install
- The `joe db` namespace anticipates further database utilities
- Core tools (in `internal/tools/core/`) reach the server's API via `internal/client/`; shared tools (in `internal/tools/shared/`) are Go-native
- Category-based observability API: `POST /api/v1/observe/{metrics,logs,traces,alerts,k8s}` resolves backend via graph edges
- Build-identity surface: `GET /api/v1/version` serializes the full `buildinfo.Info` (`version`/`commit`/`build_time`/`ui_digest`) and is the single place `ui_digest` is read; `GET /api/v1/status` reports only `version` (no digest). The `joe_build_info` Prometheus gauge (constant `1`, build identity in labels, registered in the metrics-setup layer beside the business gauges) carries the same fields; its `ui_digest` label makes a stale UI embed visible across replicas. `ui_digest` is a sha256 over the embedded UI bytes the binary serves, recomputable byte-for-byte by an external harness per the canonical serialization documented on `buildinfo.Compute`
- Every `rbac.PolicyEngine` is constructed at the **composition root** (`cmd/joe/server.go`) and injected into its consumer — never built inside a downstream package. The human-facing transport engine is built in `buildHTTPHandler` and passed into `api.New`, which hands that one engine to both the guarded accessor and the regime handler; the `agent:core` refresh engine is built beside it and threaded onto the refresh accessor. Component RBAC enforcement lives in the guarded accessor (`internal/access`), the sole authoritative gate on both the HTTP and agent-loop paths. The former `rbac.EnforcementMiddleware` — a pass-through since the D-0008 demotion whose sole consumer (the transport chain) fed it the governance-wired engine and then discarded the decision, masking the *second, bare* engine `api.New` built for the accessor — is deleted along with that second engine (rbac-engine-split): the transport and accessor now provably share one governance-wired engine. The static guard `TestGuard_PolicyEngineConstructedOnlyAtCompositionRoot` (`internal/rbac`) forbids any `rbac.NewPolicyEngine*` constructor call outside `cmd/joe` and `_test.go` files
- The registered-external-system entity is a "component" (`store.Component`, `components` table). "source" was renamed per D-0021. D-0021 deliberately spared the unrelated `knowledge_sources` table from that rename; D-0113 has since dropped it, so "component" is now the only surviving entity the word ever covered
- Panic state persisted to the `cluster_panic_state` DB row (single row, id=1) via `internal/store/panic_store.go` — there is no `panic.state` file; safe mode raises the write floor, which blocks the Mutate class in the executor
- MCP server (`joe mcp`) reads `JOE_SERVER` + `JOE_API_KEY` env vars
- Joe speaks MCP in one direction only: it runs as an MCP server (`joe mcp`), exposing its own governed tools, but deliberately does NOT act as an MCP client / consume external MCP servers' tools — the protocol has no enforceable tool mutation classification, so consuming it would reduce the machine-checkable observe-mode write-floor guarantee to an operator promise (see D-0067)
- **repo-specific override:** do not add a `Co-Authored-By` trailer to commit messages

## Reference Documents

**Tense-and-subject convention for `docs/reference/`.** A reference doc describes what the binary **is**, not what the repository **did**. The test is tense and subject together. A **past-tense statement whose subject is the repository or the codebase** — that a subsystem was removed, a surface deleted, a guard collapsed, a tree used to hold something — does **not** belong in a reference doc: a reader cannot verify it against the binary, it decays into trivia as the change recedes, and `docs/project/DECISIONS.md` is already its home and its authority. Delete such statements outright; do not rewrite, footnote, or relocate them into a historical-notes section. If the fact is not already recorded in `DECISIONS.md`, that is a separate defect to report, not a reason to keep the prose.

A **present-tense statement whose subject is the binary stays, including a negative one.** That Joe registers no file or command tool on any surface, that it is not an MCP client, that it ingests no kubeconfig, that the act-policy allow branch is reachable by no registered tool — these are structural invariants, checkable against the tree, and several are the surviving form of a guarantee whose enforcing code was deliberately deleted. Deleting them loses real meaning. The failure mode to guard against when applying this convention is **over-deletion, not under-deletion**. A citation attached to a present-tense claim is a pointer, not history, and stays. Where a single sentence carries both a historical clause and a live claim, cut the clause and keep the claim. Where a whole section's organizing premise is what used to exist, rebuild it as a present-tense description of what the thing now is (D-0126).
