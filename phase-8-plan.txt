STEP 2 — Draft Generator (T2)
------------------------------------------------------------
[ ] 2a. Create internal/knowledge/drafts/generator.go
        Generator struct with:
          - svc *knowledge.Service (for Search)
          - proposalSvc *proposals.Service
          - llm llm.LLMAdapter
          - confluenceCfg / notionCfg (or looked up dynamically from sources)

        Generate(ctx, req GenerateRequest) (*proposals.Proposal, error):
          1. Search knowledge store for relevant entries (svc.Search)
          2. Fetch current content from target (Confluence GET / Notion GET /
             Git read) — use existing read adapter functions
          3. Call LLM: current content + relevant knowledge + user context
             → proposed content (markdown or storage format)
          4. Compute unified diff (strings.Split + diff logic or
             use "github.com/sergi/go-diff/diffmatchpatch")
          5. Persist Proposal{status:pending} via proposalSvc.Create
          6. Return created proposal

        Pattern: mirrors internal/knowledge/learning/extractor.go
          (LLM system prompt → JSON response → persist)

[ ] 2b. Create internal/tools/core/generate_doc_draft.go
        Tool name: "generate_doc_draft"
        Parameters:
          topic       string (required) — what to document
          target_type string (required) — confluence|notion|git
          target_id   string (required) — page ID / file path
          context     string (optional) — extra guidance for LLM
        Returns: {"proposal_id": "...", "title": "...", "diff_preview": "..."}

[ ] 2c. Update internal/safety/tier.go
        Add to T2 section:
          "generate_doc_draft": {Tier: TierRecord, PolicyKey: "draft_generation",
           Description: "Generate a documentation draft proposal from knowledge store"}

[ ] 2d. Run: go build ./... && go test ./...

STEP 3 — Write Adapters + Publish Tool (T3)
------------------------------------------------------------
[ ] 3a. Create internal/knowledge/sync/confluence/write.go
        UpdatePage(ctx, cfg *Config, pageID, title, content string,
                   version int) error
        Uses: PUT /wiki/api/v2/pages/{id}
        Body: {"id":..., "status":"current", "title":...,
               "body":{"representation":"storage","value":...},
               "version":{"number":...}}
        Reuse: Config struct from confluence.go, same Basic auth pattern

[ ] 3b. Create internal/knowledge/sync/notion/write.go
        UpdatePage(ctx, cfg *Config, pageID, content string) error
        Uses:
          1. PATCH /v1/pages/{id} with {"archived":false} to ensure active
          2. GET /v1/blocks/{id}/children + DELETE existing paragraph blocks
          3. PATCH /v1/blocks/{id}/children with new paragraph blocks
        Reuse: Config struct, auth header pattern from notion.go

[ ] 3c. Create internal/adapters/git/docwrite.go
        CommitAndPush(ctx, repoURL, branch, filePath, content,
                      commitMsg string, auth AuthConfig) error
        Uses go-git (already a dependency):
          1. Clone/open repo locally (temp dir or configured path)
          2. Pull latest
          3. Write file content
          4. git add
          5. git commit (author: "Joe <joe@localhost>")
          6. git push

[ ] 3d. Create internal/tools/core/publish_doc_update.go
        Tool name: "publish_doc_update"
        Parameters:
          proposal_id string (required)
        Logic:
          1. Load proposal — must be status=approved
          2. Dispatch by target_type:
             - confluence → confluence.UpdatePage(...)
             - notion     → notion.UpdatePage(...)
             - git        → git.CommitAndPush(...)
          3. proposalSvc.MarkPublished(id)
          4. Return {"status":"published","proposal_id":"...","target_url":"..."}

STEP 5 — Drift Detection (T1)
------------------------------------------------------------
[ ] 5a. Create internal/knowledge/drift/detector.go
        Detector struct with svc *knowledge.Service

        DriftReport struct:
          EntryID         string
          Title           string
          SourceType      knowledge.SourceType
          SourceURL       string
          ExternalChanged bool    -- external doc changed since last sync
          LocalChanged    bool    -- knowledge entry changed without re-sync
          Diff            string  -- unified diff if content differs
          DetectedAt      time.Time

        Detect(ctx, entryID string) (*DriftReport, error):
          1. Load entry from knowledge store
          2. Fetch current external content (Confluence GET / Notion GET /
             Git file read)
          3. Compare SHA-256 hash vs stored content_hash
          4. If different: compute diff, return DriftReport{ExternalChanged:true}

        DetectAll(ctx, sourceType) ([]*DriftReport, error):
          - Lists Tier 2 entries (optionally filtered by source_type)
          - Calls Detect on each, collects non-empty reports

[ ] 5b. Create internal/tools/core/detect_doc_drift.go
        Tool name: "detect_doc_drift"
        Parameters:
          source_type string (optional) — filter: confluence|notion|git
          entry_id    string (optional) — check single entry
        Returns: {"drifted_count":N, "reports":[...]}

[ ] 5c. Update internal/safety/tier.go
